## Claude Code marketplace (plugins)

### Layout

This repo is a Claude Code marketplace holding several mods under `plugins/<name>/`, listed in `.claude-plugin/marketplace.json`. The tooling (package.json, ESLint, Prettier, husky) is shared at the root, and each plugin is a pnpm workspace package (`pnpm-workspace.yaml`, with `typescript` pinned in its `catalog`).

The per-plugin root scripts (`types:gen`, `types:check`, `validate`, `test`) run `pnpm -r exec` over the plugins, while `lint` and `format` run once at the root. So a new plugin needs a bare `package.json` (copy `plugins/hud/package.json`) but no script or CI change. See the Layout in `DEVELOPMENT.md`.

Setup, running, scripts and prerequisites are in `DEVELOPMENT.md`; `README.md` is for end users only. The type generation script is in `package.json`.

### Types and engine quirks

A plugin's hooks import types from `'claude-code'`, which only exist after the engine lays them into `plugins/<name>/.claude-plugin/types/` (gitignored, generated by `pnpm types:gen`).

A function that receives `$` and lives in another file must be a `function` declaration, not a `const` arrow, or `claude plugin validate` rejects it.

JSX `<>` compiles to the engine's `Fragment`, a column Box, so it cannot sit inside a `<Text>`; wrap inline siblings in a nested `<Text>` instead. The failure shows only at render time ("Box inside an inline element"), and `tsc` does not catch it.

`claude plugin validate` notes "gating hook without .catch" and `tool.call{tool=?}`. Neither is a problem, and `--strict` passes:

- `.catch` matters only for hooks that refuse (guards), not observers that call `next`.
- `tool=?` only means the filter is not a literal; it still applies at runtime.

### CI and tooling

CI (`.github/workflows/check.yml`) runs `types`, `lint`, `format`, `validate` and `test` as separate jobs, each using the `.github/actions/setup` composite action. CI generates the types with a placeholder API key, because the engine writes them before the model call fails; see the comment in that action.

The CLI version CI installs is pinned in `.github/actions/setup/action.yml` and bumped by Renovate through its `# renovate:` comment (the shared preset's `customManagers:githubActionsVersions`). `validate` and `test` need neither a login nor the generated types.

Type-aware ESLint (`projectService`/`project`) was tried and abandoned: a single typed rule ran for over 3 minutes without finishing on this tiny repo, while `tsc` takes under a second.

## HUD status bar (`plugins/hud`)

### Where things are

- User-facing behaviour, colours and thresholds: `plugins/hud/README.md`.
- File map: `plugins/hud/DEVELOPMENT.md`.
- Code: `plugins/hud/hooks/status-bar/`. `data.ts` reads the engine into a `ClaudeState` and a `WorkspaceState`, refreshed separately, and `render.tsx` draws them.

### Look

Icons must be emoji that are wide by default (East Asian Width `W`), never a narrow symbol plus the U+FE0F variation selector (⬆️, 🏷️). Terminals disagree on how many columns that pair takes, which shifts the text after it.

Yellow, orange and red belong to the `warning` and `critical` levels only. Every other part of the bar uses a colour that does not read as a warning.

Each row is a `flexWrap="wrap"` Box of sections, and each section a Box of section items, every section item a Box holding one `Text` that truncates on its own. A section truncates only when it alone is wider than the row, and its `•` trails it outside the truncation. Tests cannot see the paint, so confirm wrapping in a terminal after changing it.

### Keys

Only a `Box` keeps a `key` in the tree a test reads (`TextProps` has none), and the engine treats it as a name for finding the Box and as a hover scope. So whatever a test selects is drawn as a Box.

The keys nest, dash-separated within an id and joined by `:`: `claude-row:claude-model:name` for a section item, `claude-row:claude-model:separator` for the separator after a section. Tests write them out in full as string literals, as Testing Library does for test ids, and select by key only where the text carries a live figure.

### Workspace and state

The bar shows `$.session.cwd()` on purpose, so it follows the agent into a scratch directory; `$.session.root()` was tried and rejected. `WorkspaceState` keeps `cwd` apart from `git`, and the row that shows both is called `workspace`.

The figures live in `$.state` (`hud.claude` and `hud.workspace`). They are declared once in `plugins/hud/types/index.d.ts` and named by `types` in `plugin.json`, and `data.ts` and `render.tsx` derive their types from it. The engine's scan wants each `update`/`read` reference written out as string literals at the call, in the file that uses it, so an atom shared across files is rejected.

`/clear`, `/resume` and `/branch` reset `$.state` without firing `session.start`, so a `classic.SessionStart` hook for those sources refreshes both once. The 60-second timer from `session.start` keeps running.

The workspace refreshes on `classic.CwdChanged` as well as after file-changing tools, so a worktree switch (`EnterWorktree`/`ExitWorktree`, which are not in `WORKSPACE_CHANGING_TOOLS`) shows at once. Whether the engine fires it for worktree switches is unconfirmed; check in a real session. A hot reload cancels the plugin's `$.clock.every` timers, and the next `session.start` sets it again.

### Git

Two facts about the git commands:

- `--porcelain` ignores most user config, but not the `-u` default: `status.showUntrackedFiles=no` hides untracked files unless `--untracked-files=normal` is passed (verified).
- `describe --exact-match --always` does not fall back to a sha (exits 128), which is why the detached path still needs `rev-parse`.

`runGit` throws when git cannot run, and returns `""` for a non-zero exit (not a repository). The branch comes from the `# branch.head` line of the one `status --porcelain=v2 --branch` call, and `describe`/`rev-parse` run only when it says `(detached)`.

`refreshWorkspace` keeps the last git details when any of them throws, so a timed-out `status` is never read as a detached HEAD or as a non-repository. The cost is that a `status` slow enough to time out also hides the branch, which a separate `symbolic-ref` used to keep showing.

`$.process.run` kills a child after 30 s by default and rejects, so a hung git cannot wedge `singleFlight`. Output past 4 MiB is dropped with a normal exit code (`isStdoutTruncated`).
